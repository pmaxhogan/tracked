# Pre-save, mkvid track uploads, and the data table — build spec (2026-10-08)

The owner asked for (speech-to-text, paraphrased):

1. **Pre-save** a track 1001tracklists has identified but has no YouTube video for — every case: only a Spotify link, Spotify + Apple, some other combination, only a 1001tracklists track page, or just an "ID" with no link at all. Pre-save from Tasker, from the Set page and from the DJ profile. Pre-saving puts it in a queue that is rechecked (twice a day). A **Pre-saves** page shows the queue: tap a track to recheck it now, see its status, links to it on 1001tracklists and every other site it is linked on, and the history of every check and its result. Sort and filter, including the ones already found. When one is found: **push to all devices**, tap → the `music.youtube.com` version of the YouTube link (else a dedicated track page with an obvious one-click button).
2. A **data table component** with server-side sorting, filtering, search and paging on any column, column types (number ranges, date before/on/after/between with date pickers, enums, text, bool), filter chips, header click sort (asc → desc → none), a filter dropdown per column, rows that belong together kept together ("two IDs tied together": a `w/` row stays with its base), pagination with total count, first/prev/numbered/next/last, jump to page, rows per page (default 50). Replace **every list in the UI** with it, with server-side refactors where needed.
3. **mkvid track uploads**: a pre-saved track watched ≥ 5 days that has a link on a site yt-dlp supports but no YouTube link is, when rechecked, put into a new queue for mkvid. Own page. Ban a bad source URL. Every mkvid track upload goes into one playlist **"Track uploads"** (created if missing, id stored). A different visualizer from the sets'. Push "track ripped and uploaded" when one is uploaded.
4. Everything configurable on settings pages.

## Shared vocabulary

- **Medialink sources** (1001tl `get_medialink.php`, `source` code → name): `1` beatport, `2` apple, `4` traxsource, `10` soundcloud, `13` youtube, `36` spotify. Unknown codes are kept as `src<code>`. Entries come in `data` (players: `player` iframe HTML, `playerId`, `duration` seconds as a string) and `more` (`idLink`). The YouTube link is `more[source=13].idLink` (and possibly `data[source=13].playerId`).
- `LinkEntry = { source: string /* code */, name: string, url: string | null, playerId: string | null, duration: number | null }` — `url` is a canonical public URL where one can be built: spotify `https://open.spotify.com/track/<id>`, apple (as today's `buildAppleLink`), soundcloud `https://api.soundcloud.com/tracks/<id>` (what yt-dlp takes; the widget URL is fine for display), youtube `https://www.youtube.com/watch?v=<id>`, beatport `https://www.beatport.com/track/-/<id>`, traxsource `https://www.traxsource.com/track/<id>`; otherwise the iframe `src`.
- **YouTube Music link**: `https://music.youtube.com/watch?v=<videoId>`.

## Pre-save (agent PRESAVE)

Schema: `migrations/0016_presaves.sql` (read it; it documents every column).

**Saving** — `addPresave(env, input, source)` with `input = { trackId?, trackUrl?, setUrl?, rowIndex?, cueSeconds?, artist?, title?, artworkUrl?, label?, djSlug? }`:
- numeric `trackId` → identity by `track_id`, stage `links`.
- no `trackId` but a `trackUrl` (`/track/1hf79cg5/tobehonest-where-ya-at/index.html`): the slug id in a track URL is **not** the medialink id (that row's medialink id is `909720`; verified on `test/fixtures/tracklist-matroda.html`). Resolve it: (1) if a `setUrl` is given, find the row with that `trackUrl` in the cached parsed set and take its `trackId`; (2) else fetch the track page itself through the pool (kind `set`, one page view; add a small parser for the medialink id it embeds — `data-trackid` / `idItem`, write a fixture-free defensive parser and log what it found) — at `phone` priority for a manual save; (3) still unknown → stage `identify` keyed by `track_url` (add it to the identity: a unique `track_url` while `track_id` is null is fine to enforce in code), rechecked by step (2).
- no id at all (anonymous "ID - ID" or "Artist - ID" row) → identity by `(set_url, row_index)` with `cue_seconds` and `prev_track_id` / `next_track_id` anchors; stage `identify`.
- Idempotent: saving an already saved track returns it (`created: false`), and restores it if dismissed.
- Saving runs an immediate check (trigger `add`) unless the caller says `check: false`, but a pool refusal there only records `pool_refused` — it never fails the save.

**Checking** — `recheckPresave(env, id, trigger, opts)`:
- stage `links` (has `track_id`): an **uncached** medialink lookup (write-through to `ml:v1:<id>`, which must be refreshed, not consulted) at `settings.presave.priority` for `scheduled`, `phone` for `manual`/`add`. Parse **all** sources. A pool refusal / failed lookup is result `pool_refused` (or `error`): nothing else changes, `fail_count++`, next check after `retryMinutes`, and for a scheduled run it must reach the scheduler as a refusal so the tick stops (throw the typed pool error after recording, or return a flag the tick reads).
  - a YouTube link → stage `found`, `youtube_video_id`, `found_at`, push (`presave_found`, url `https://music.youtube.com/watch?v=<id>`, title `Pre-saved track is on YouTube`, body `<artist> – <title>`) when `notifyFound`, `notified_at`; supersede any live track upload (`supersedeTrackUploadsForPresave`, TRACKUP).
  - no YouTube link → result `no_youtube`, store links, then call `maybeQueueTrackUpload(env, presave)` (TRACKUP) which decides by itself.
- stage `identify`: read the set page (the cached parsed list when it was fetched after `last_checked_at`, else a fresh fetch through `resolveTracklistPage`-like code at the scheduled priority / phone for manual). Find the row: same `cue_seconds` first (± 2 s), then the anchors (row right after `prev_track_id` / right before `next_track_id`), then `row_index`. Identified → take `track_id`, artist, title, track_url, artwork, stage `links`, `identified_at`, result `identified`, and run the links check right away in the same call. Still ID → `still_id`. Not found → `row_missing`.
- Every check appends a `presave_checks` row and updates `last_checked_at`, `check_count`, `last_result`, `last_error`, `next_check_at = now + interval × (1 ± jitter)` (null once found / uploaded / dismissed). `giveUpDays` > 0 dismisses a track watched that long (result `gave_up`).
- **Set-fetch hook** (`useSetFetches`): wherever the sync / verification / viewer parses a set page once (`README: Every page is used fully, once`), call `presaveOnSetParsed(env, setUrl, scraped)` — it updates `identify`-stage presaves of that set (cheap D1 query by `set_url`; no-op when none). Trigger `set_fetch`. It must never throw into the sync.
- **Scheduler**: a new tick item, at most `presave.maxPerTick` per tick **in addition to** the drawn items, from `presaves WHERE next_check_at <= now AND stage IN ('identify','links')` oldest-due first; respects pause / tick backoff like every item; a pool refusal stops the tick as usual. Recorded in the tick history like other items (kind `presave`).

**Anonymous rows reach the UI**: `/ui/api/tracklist` (and `POST /tracklist`) gain `rows: RowOut[]` — every page row, anonymous ones included, each `{ rowIndex, cueSeconds, startTime, artist, title, trackId, trackUrl, artworkUrl, isUnidentified, idStatus, isMashupLinked, anonymous }`. `tracks` stays exactly as it is (other consumers). The cached parsed list must carry the rows (check `tl:v4:` — bump the cache format version if it does not, the README explains versioning). Each `tracks[i]` also gains `rowIndex`.

**/now-playing**: each track gains `trackId` and `rowIndex` (additive; update `src/schemas.ts` and the OpenAPI).

**HTTP**
- Tasker (bearer `API_TOKEN`): `POST /presave` body `{ trackId?, trackUrl?, tracklistUrl?, rowIndex?, cueSeconds?, artist?, title?, artworkUrl? }` (at least one of trackId / trackUrl / (tracklistUrl + (rowIndex | cueSeconds))) → `200 { ok: true, created, presave: PresaveOut, message }` (`message` is a one-line human sentence for a Tasker flash, e.g. `Pre-saved: Artist – Title (watching for a YouTube link)` / `Already pre-saved …` / `Already on YouTube: …`). `400 { error, message }` on bad input. Also `GET /presave/status?trackId=|trackUrl=` → `{ presave: PresaveOut | null }`.
- UI (CF Access, under `/ui/api`):
  - `GET /ui/api/presaves` — a **data-table endpoint** (see Data table contract). Columns: `id`, `artist`, `title`, `stage` (enum identify/links/found/uploaded/dismissed), `linkSources` (enum-multi: spotify, apple, soundcloud, beatport, traxsource, youtube, none), `linkCount` (number), `durationSeconds` (number), `createdAt`, `lastCheckedAt`, `nextCheckAt`, `foundAt` (datetime, unix ms), `checkCount` (number), `lastResult` (enum), `source` (enum ui/tasker/api), `djSlug` (text), `setUrl` (text). Search `q` over artist, title, dj, set url. Default sort `-createdAt`. Also returns `counts: { identify, links, found, uploaded, dismissed }` for the chips.
  - `POST /ui/api/presaves` — same body as `/presave` → same answer.
  - `GET /ui/api/presaves/:id` → `{ presave: PresaveOut, upload: TrackUploadOut | null }`.
  - `GET /ui/api/presaves/:id/checks` — data-table endpoint over `presave_checks` (columns `at` datetime, `trigger` enum, `result` enum, `stageBefore`, `stageAfter`, `linkCount`, `linkSources`, `youtubeVideoId`, `error`, `ms`), default sort `-at`.
  - `POST /ui/api/presaves/:id/recheck` → `{ presave, check }` (manual, phone priority; a pool refusal answers 503 `{ error: 'pool_busy', message }` with the check recorded).
  - `POST /ui/api/presaves/:id/dismiss`, `/restore` → `{ presave }`. `DELETE /ui/api/presaves/:id` → `{ deleted: true }` (also deletes its checks).
  - `POST /ui/api/presaves/lookup { trackIds?: string[], setUrl?: string }` → `{ byTrackId: { [id]: { id, stage } }, byRow: { [rowIndex]: { id, stage } } }` so track rows can show "Pre-saved" state.
- `PresaveOut = { id, trackId, trackUrl, setUrl, rowIndex, cueSeconds, artist, title, artworkUrl, label, djSlug, stage, links: LinkEntry[], linkSources: string[], linkCount, durationSeconds, youtubeVideoId, youtubeUrl, youtubeMusicUrl, source, createdAt, updatedAt, lastCheckedAt, nextCheckAt, checkCount, failCount, lastResult, lastError, identifiedAt, foundAt, notifiedAt, dismissedAt, uploadEligibleAt }` — times are unix ms; `uploadEligibleAt = createdAt + minWatchDays`.

## Track uploads (agent TRACKUP)

Schema: `migrations/0017_track_uploads.sql`.

- `maybeQueueTrackUpload(env, presave: PresaveRow)` — called by PRESAVE after every check that ends without a YouTube link. Queues when: `trackUploads.enabled`, stage `links`, `now - created_at >= minWatchDays`, no live request for this presave, and an allowed, unbanned source: walk `allowedSources` in order, take the first link entry whose `name` matches and whose `url` is not in `track_upload_bans`. Insert `pending`. Returns `{ queued: boolean, reason }`. Log `track_upload.queued`. Never throws.
- `supersedeTrackUploadsForPresave(env, presaveId, why)` — live requests → `superseded`.
- mkvid contract (bearer `MKVID_TOKEN`, sub-app mounted at `/mkvid/track`, excluded from the API_TOKEN wildcard like `/mkvid`):
  - `POST /mkvid/track/claim { accounts?: ('primary'|'shared')[] }` → `{ request: TrackRequest | null }`. Claims the oldest claimable (pending past `not_before`, or claimed past the mkvid claim TTL) while today's track claims < `trackUploads.dailyCap` **and** the account has room under mkvid's per-project caps (reuse `lib/mkvid.ts`'s cap logic; append a `mkvid_claims` row with `request_id = 'track:<id>'` so the per-project upload count includes tracks). Optimistic claim like `tryClaimRow`.
  - `TrackRequest = { id, presaveId, artist, title, artworkUrl, trackUrl, sourceName, sourceUrl, expectedDurationSeconds, minDurationRatio, privacy, account, attempts }`.
  - `POST /mkvid/track/job { id, jobId }` (renews the claim). `POST /mkvid/track/complete { id, videoId, videoUrl?, privacy?, jobId? }` → inserts the video into the **Track uploads** playlist (title from settings; looked up by exact title, created when missing — `public`? no: same privacy convention as the artist playlists — id stored in SUBS KV `trackuploads:playlist`; recreated if deleted), marks the request `done`, the presave stage `uploaded` with `youtube_video_id` (a `presave_checks` row, trigger `upload`, result `uploaded`), and pushes `track_uploaded` (title `Track ripped and uploaded`, body `<artist> – <title> (from <source>) is now in "Track uploads"`, url `https://music.youtube.com/watch?v=<id>`) when `notifyUploaded`. If 1001tl got a YouTube link meanwhile (presave stage `found`) still record the video but mark `superseded`, no playlist insert. Unknown id → 404.
  - `POST /mkvid/track/fail { id, error, permanent?, jobId? }` → backoff `retryBackoffHours × attempts`, `failed` after `maxAttempts` or when permanent; a claim given back refunds its `mkvid_claims` row (like `/mkvid/fail`).
  - `GET /mkvid/health` gains `trackUploads: true`.
- UI API (`/ui/api/track-uploads`): data-table endpoint over `track_uploads` (columns `id`, `artist`, `title`, `sourceName` enum, `sourceUrl`, `status` enum, `attempts`, `createdAt`, `claimedAt`, `completedAt` datetime (unix s → expose ms), `videoId`, `error`, `account` enum), default sort `-createdAt`, plus `counts` per status and `today: { claims, cap }`; `POST /ui/api/track-uploads/:id/retry`; `POST /ui/api/track-uploads/:id/ban-link { reason? }` (bans its `source_url`, marks it `banned`, then calls `maybeQueueTrackUpload` for the presave so the next allowed source is queued); `GET /ui/api/track-uploads/bans` (data table: `url`, `sourceName`, `reason`, `bannedAt`); `POST /ui/api/track-uploads/bans/unban { url }`; `POST /ui/api/track-uploads/ban-url { url, reason? }` (ban without a request, e.g. from the presave page); `GET /ui/api/track-uploads/playlist` → `{ playlistId, title, url }`.

## Data table (agent TABLE)

**HTTP contract** (every table endpoint):
- `page` (1-based, default 1), `size` (default 50; 10–200).
- `sort` = comma list of column keys, `-` prefix = descending (`sort=-createdAt,title`). Empty = the table's default sort. A tiebreak on the primary key is always appended.
- `q` = free-text search over the table's searchable columns (case-insensitive contains).
- `f.<col>` = `<op>:<value>`, repeatable (AND). Ops by column type:
  - `text`: `eq`, `ne`, `has` (contains), `nhas`, `sw`, `ew`, `empty`, `nempty`
  - `number`: `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `between` (`a..b`, either side may be blank), `empty`, `nempty`
  - `datetime`: same as number, values are **unix ms** (the client turns a date picker's local day into a ms range)
  - `date` (stored `YYYY-MM-DD`): `eq`/`on`, `before`, `after`, `between` with `YYYY-MM-DD` values, `empty`, `nempty`
  - `enum`: `in` (`a|b|c`), `nin`; for a multi-valued enum column (stored `,a,b,`) `in` means "has any", `all` "has all"
  - `bool`: `eq:1` / `eq:0`
- Answer: `{ rows, total, page, size, pageCount, sort: [{ col, dir }], filters: [{ col, op, value }], q }` plus whatever extra the endpoint adds (counts, facets). An unknown column, op or bad value is `400 { error: 'bad_table_query', message }`.
- Server lib (`src/lib/table-query.ts`): a table definition (`columns: { key: { sql, type, sortable?, filterable?, searchable?, storage?: 'ms'|'s'|'iso' } }`, `from`, `where?`, `defaultSort`, `primaryKey`), `parseTableQuery(params, def)`, `runTableQuery(db, def, query, extra?)` (one `COUNT(*)` + one page query, all binds, no string interpolation of values), and `runLocalTable(rows, def, query)` with identical semantics for lists that are computed or merged in the Worker. **Groups**: a definition may declare `group: { key, isChild }` so a child row (a `w/` row) is ordered right after its parent whatever the sort (the group sorts by its lead row); supported in `runLocalTable` and the client's local mode, and in SQL where the definition supplies the group's sort expression.

**Client component** (`src/ui/data-table.ts` → `DATA_TABLE_CSS`, `DATA_TABLE_JS` defining one global `TKTable`, embedded by the shell on every page after the runtime; define-only at load: no timers, no fetches, no DOM access, survives `minimalStub`). Renders through `innerHTML` strings and delegated `closest()` clicks (the `richStub` convention). `TKTable.create(el, config)`:
- `id` (URL state prefix, e.g. `t1.page`, `t1.sort`, `t1.f.stage`; `urlState: false` to opt out), `source: { url, params?: () => obj }` (server mode) or `{ rows: array | () => array }` (local mode, same semantics client-side), `columns: [{ key, label, type, sortable, filterable, options, render(row) → html, align, width, hideOn: 'phone', tip }]`, `defaultSort`, `pageSize` (50), `pageSizes` ([10, 25, 50, 100, 200]), `search` (placeholder) or false, `chips: [{ id, label, filters, sort?, group? }]` (preset filters; chips in the same `group` are exclusive) plus removable chips for every active filter, `rowKey`, `rowAttrs(row)`, `onRowClick(row, ev)`, `actions(row) → html` with `data-act` buttons and `onAction(act, row, btn)`, `group: { key(row), isChild(row) }`, `empty` text, `swr` (paint the stored first page first), `onData(resp)` (for counts), `compact` (no toolbar/pager, for previews).
- Header: click cycles sort asc → desc → none; shift-click adds a secondary sort; sort arrows and priority numbers; a filter button per filterable column opens a popover with the type's ops (number min/max, date pickers with before/on/after/between and quick ranges, enum checkboxes, text contains/equals/…).
- Pager: "1–50 of 1,234", first / prev / numbered pages with ellipses / next / last, a jump-to-page input, a rows-per-page select. Loading state keeps the old rows dimmed; skeleton on first load; stale responses are dropped (sequence guard / AbortController).
- Phone (< 700 px): rows become cards (`td[data-label]`, like `.tk-table` today).
- Returns `{ reload(), setFilter(col, op, value), clearFilters(), state(), rows() }`.
