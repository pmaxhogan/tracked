# tracked web UI: client behaviour contract

What every rebuilt page must keep doing. Extracted from the inline scripts at `d5ab9c4` (`src/routes/subscriptions.ts`, `pool-ui.ts`, `ban-ui.ts`, `playlist-hygiene.ts`) and the tests that pin them. Paths are written with the new `/ui` prefix (the pages move from `/subscriptions` per the design spec, section 3a); the old code is the source of truth for anything not listed here: `git show d5ab9c4:src/routes/<file>`.

Copy quoted here is verbatim from the old code where wording matters (status lines, badges, confirmations, empty states). Keep it unless the design spec changes it.

## 0. Cross-cutting

- Every fetch: `credentials: 'same-origin'`. Every non-GET: `content-type: application/json`, body `'{}'` when empty. The `method: 'POST'` literal and the header must sit in one object literal (`test/same-origin.test.ts`); the `/ui` page needs more than two such fetches; the pool page must contain the verbatim `headers: { 'content-type': 'application/json' }`.
- Script tags are bare `<script>` with no attributes; every inline script parses with `new Function` / `new vm.Script`.
- Tests run page scripts in a stub DOM. Stub elements expose only: `innerHTML textContent value hidden checked disabled className src dataset style options addEventListener focus add remove showModal close querySelector querySelectorAll(->[]) closest(->null)`; `document` has `getElementById hidden addEventListener querySelector(->null)`; globals `fetch setTimeout clearTimeout setInterval clearInterval Option console Date`. On the pool pages do not use `classList`, `replaceWith` or `insertAdjacentHTML`. `BAN_JS` runs with stub elements that expose only `textContent innerHTML hidden addEventListener classList.toggle`, plus `navigator: {}`, `window.isSecureContext: false`, `sessionStorage`, `alert`.
- Escaping: main and pool pages use `esc()` (`& < > " '`, null -> '') over innerHTML; tracklist, DJ and removed pages use `createElement` + `textContent` and set `href` only for `http(s)://` URLs.
- Headers: pages and APIs send `X-Frame-Options: DENY` + `frame-ancestors 'none'`; the live view gets `SAMEORIGIN` + `frame-ancestors 'self'`. Pages are `Cache-Control: no-store`; `sw.js` is `no-cache`.
- Server-side helpers the pages rely on (unchanged): `extractVideoId` (bare 11-char id, `youtu.be/<id>`, `youtube.com` / `www.` / `m.` / `music.` with `?v=` or `/embed|shorts|live|v/<id>`), `parseDjSlug` (bare slug or a `1001tracklists.com/dj/<slug>` URL; lowercased; rejects other hosts).

## 3. mkvid

API: `GET /ui/api/mkvid?limit=25&section=all|queue|settled[&status&source&dj&q]`; `queueCursor` only with `section=queue`, `settledCursor` only with `section=settled`; cursors are opaque and echoed back. Response: `queue[] queueCursor queueTotal settled[] settledCursor settledTotal counts{pending claimed done failed superseded banned} accounts[{account label cap used}] lastPoll{at outcome accounts[]} dailyClaimCap dailyClaims enabled now quotaResetsAt oldStyleCount oldVideos[] djs[{slug label count}]`. Each queue row carries `position` (server-side ROW_NUMBER over the whole pending queue): display `#N`, never count locally. A sequence counter makes only the newest load render. Section `all` replaces both lists and the header; `queue`/`settled` append.

Filters: search (`input type=search`, placeholder "search set, DJ or URL", 250 ms debounce); status select options `""` any status, `pending` waiting, `claimed` rendering, `done` uploaded, `failed` failed, `superseded` superseded, `banned` banned, `failed,banned` problems only; source `""` any source, `soundcloud` SoundCloud, `hearthis` hearthis.at; DJ select rebuilt from `djs` as `{label} ({count})`, preserving the current value (appended if no longer present); Clear shown only when filtered; every change reloads section `all`.

Status line `mkState(d)` -> `[cls, title, sub]`, first match (`eff = mkEffective(d)`: accounts offered by the last poll, or all when the poll names none; `silent = !poll || now - poll.at > 25*60`; `idleNote` lists accounts with cap left that mkvid has not connected):
1. `!enabled`: bad, `Off — MKVID_TOKEN is not set`, `Nothing is queued and mkvid cannot claim.`
2. `dailyClaimCap === 0`: bad, `Paused — every daily cap is 0`, `MKVID_DAILY_CLAIM_CAP (and MKVID_SHARED_DAILY_CLAIM_CAP) refuse every claim. Set MKVID_DAILY_CLAIM_CAP to 24 (or delete the secret) to resume.`
3. `counts.claimed`: ok, `Rendering N set[s] now`, `{used}/{cap} of today’s uploads used.`
4. silent: bad, `mkvid last polled {relTime(poll.at)}` or `mkvid has not polled yet`, `It normally polls every minute. Check the mkvid container on the NAS and that it can reach this Worker (TRACKED_URL / TRACKED_TOKEN).`
5. `poll.outcome === 'error'`: bad, `The last claim failed on the Worker side`, `Usually a transient D1 error; mkvid retries every minute.`
6. `poll.outcome === 'not_connected'`: bad, `mkvid has no YouTube account connected`, `Its token expired or was revoked. Open mkvid.maxhogan.dev and connect YouTube again.`
7. `!counts.pending`: ok, `Queue empty`, `Nothing is waiting for mkvid.`
8. `eff.used >= eff.cap || poll.outcome === 'capped'`: wait, `Today’s {eff.cap} upload[s are|is] used — next one {untilTime(quotaResetsAt)}`, `The caps reset at midnight Pacific with the YouTube quota (each project allows 100 uploads a day; the caps here keep it to 30 in total).` + idleNote
9. else: ok, `Ready — mkvid takes the next set on its next poll`, `{used}/{cap} of today’s uploads used.` + idleNote
(curly apostrophes U+2019 in "today’s"/"Today’s"; `untilTime` -> `in {m}m` / `in {h}h {m}m`.)

`mkWhy(readiness, short)`: `unverified` -> `not verified` (+ ` — the track list needs a second matching fetch before anything is rendered`); `waiting_ids` -> `waiting for IDs until {YYYY-MM-DD}` (+ ` ({idRows} ID row[s]; Render now skips the wait)`); `backoff` -> `retry {untilTime}`; capped -> `capped — today’s uploads are used`; else `ready`. Tests pin the page text `Render now`, `Delete and recreate`, `Recreate all old-style videos`, `waiting for IDs until`, `not verified`, `capped`.

Summary line: `{done} uploaded · {pending} waiting · {failed} failed (warn) · {superseded} superseded · {banned} banned · {label} {used}/{cap} per account · backlog ≈ {ceil(pending/perDay)} day[s] at {perDay}/day · mkvid seen {relTime} · {n} replaced video[s] not deleted yet`; when filtered, prefixed with `{queueTotal+settledTotal} match this filter`. Recreate-all button hidden unless `oldStyleCount > 0`, text `Recreate all old-style videos (N)`. Empty: `No requests match this filter.` / `No sets queued for mkvid yet.`

Groups: Rendering now (settled with `claimed`), `Up next · newest set first` (+ ` · showing X of Y`), Replaced videos to delete from YouTube, Finished. More button `Load {min(left,25)} more ({left} left)`.

Row: `#N` or badge (`rendering` for claimed); title `setTitle || setLabel(setUrl)`; meta `setDate · artistLabel||artistName||slug · sourceLabel||source · why/retry/relTime · recreating · old style · {error}`; watch link `videoUrl || https://youtu.be/{id}`; queue actions ⤒ top "Move to the top", ↑ up "Move up one", ↓ down "Move down one", ⤓ bottom "Move to the bottom", ✕ ban "Never upload this set via mkvid" -> `POST /ui/api/mkvid/move/{id} {to}` / `POST /ui/api/mkvid/ban/{id} {}`, errors `move failed (N)` / `ban failed (N)`, then a full reload. ## 6. Pool pages (COMMON_JS, CAPTCHA_JS)
